The agent became `.md` for Claude Code and Cursor, `.toml` for Codex and `.agent.md` for Copilot.
The skill went to `.claude/skills` for Claude Code and once to `.agents/skills`, which the other three read.
`palm.yaml` lists what you asked for, and `palm.lock.yaml` records every file palm wrote.

## How it works

<CardGrid>
  <Card title="Any repository, as it is" icon="open-book">
    palm reads plugins, marketplaces, APM packages and plain `SKILL.md` folders. It detects the
    layout, so authors repackage nothing.
  </Card>
  <Card title="Native files per harness" icon="document">
    An agent becomes `.md`, `.toml` or `.agent.md`. Hooks and MCP servers merge into each tool's
    own config file, and uninstall removes exactly those entries.
  </Card>
  <Card title="Agents bring their tools" icon="puzzle">
    An agent names the skills and MCP servers it uses. palm installs them with the agent and
    removes them once nothing else needs them.
  </Card>
  <Card title="Secrets stay out of git" icon="padlock">
    Project files get each harness's environment reference, such as `${env:TOKEN}` for Cursor. The
    lockfile stores the placeholder, never the value.
  </Card>
</CardGrid>

## Where files go

Project scope, for the four targets palm supports today.
The [targets matrix](/palm/reference/targets-matrix/) adds commands, hooks, global paths and the targets planned for 1.0.

<div class="palm-wide">

| Kind | Claude Code | Codex | GitHub Copilot | Cursor |
| --- | --- | --- | --- | --- |
| skill | `.claude/skills/<n>/` | `.agents/skills/<n>/` | `.agents/skills/<n>/` | `.agents/skills/<n>/` |
| agent | `.claude/agents/<n>.md` | `.codex/agents/<n>.toml` | `.github/agents/<n>.agent.md` | `.cursor/agents/<n>.md` |
| instruction | `.claude/rules/<n>.md` | block in `AGENTS.md` | `.github/instructions/<n>.instructions.md` | `.cursor/rules/<n>.mdc` |
| mcp | `.mcp.json` | `.codex/config.toml` | `.vscode/mcp.json` | `.cursor/mcp.json` |

</div>

## Compared with other tools

Checked on 2026-09-28 against each tool's documentation and source.
"n/a" marks a cell we have not verified.

<div class="palm-wide">

| | palm | Microsoft APM | skills.sh | Claude Code `plugin` | Copying by hand |
| --- | --- | --- | --- | --- | --- |
| Kinds | all 7 | all 7, plus LSP servers and binaries | skills | 6, no instructions | any |
| Harnesses | 4, with 6 planned for 1.0 | 13 | 79 | 1 | each one by hand |
| Repositories as published | yes, with a layout override | 6 fixed layouts | skill folders | needs `marketplace.json` | yes |
| Lockfile | commit, hashes, every file and merged entry | commit, file hashes, `--frozen` | no commit pinning | per user, no pinning | none |
| Secrets in project files | an environment reference per harness | literal values for Cursor, Codex and Gemini | no MCP servers | `${VAR}` references | by hand |
| Agent dependencies | installed and reference-counted | declared by the author in `apm.yml` | no agents | n/a | by hand |
| License | MIT | MIT | MIT | proprietary | none |

</div>

APM covers more harnesses and ships native binaries.
skills.sh reaches the most agents, for skills only.
palm covers every kind across four harnesses, from repositories as they are published.
