palm installs files from repositories you choose.
Most of them are text, but hooks and stdio MCP servers run programs on your machine.
palm shows you those programs before it writes them, pins your consent to their exact bytes, and refuses content that can hide instructions.

```sh
palm install trailofbits/skills plugin:gh-cli --dry-run
```

`--dry-run` prints every program the install would add, with its scripts, and writes nothing.

## What you trust

A source is code you chose, the same way a dependency in `package.json` is.
Declaring one in `palm.yaml` is a decision to trust its author, and it shows up in review like any other dependency.
palm does not rank, scan for intent or sandbox what a source contains.

| Kind | What it can do |
| --- | --- |
| skill, agent, instruction | Shape what the model does. The harness decides which tools the model may use. |
| hook | Runs a shell command on a harness event, with your permissions. |
| mcp, stdio | Starts a local program and exposes its tools to the model. |
| mcp, remote | Connects to a URL and exposes that server's tools. Nothing runs locally. |

## Programs need a yes

Before palm writes a hook or a stdio MCP server, it shows the source, the commit and its date.
It shows every command as the harness will run it and the files it lands in.
It lists every script with its mode, size and hash.

- The default answer is no. Enter declines.
- `--yes` never consents. It covers plan confirmations only.
- Consent is a hash over the commands, events, matchers, environment keys, working directory and every script byte and mode bit. Any change asks again.
- The hash covers the scripts of an in-repo source too, read from the working tree, and every file a script reads through a literal path.
- The hash goes into the lock as `trust:`. Teammates and CI install the same program without a prompt, and a changed one fails CI until someone reviews it.
- Without a terminal, only an `--allow-exec` line with the exact hash consents.
- The hash pins the command text, not what `npx -y <package>` downloads at run time. Pin a version in the command to pin the code.

[Consent and executable content](/palm/concepts/consent/) shows the prompt and the lock record.

## Scripts are committed

palm copies what a hook runs into `.palm/assets/<source>/<entity>/`, and you commit it.
An in-repo source's scripts are not copied, because they already live in the repository.
A reviewer reads the script in the same pull request as the hook command.
A clone without palm never runs a command that points at a missing file.
palm does not mark the folder as generated for GitHub's diff view, because reviewers should read it.

## What palm refuses

| Refused | Rule |
| --- | --- |
| Names that escape | An entity name is one path segment of letters, digits, `.`, `_` and `-`, never `..`. |
| Symlinks that escape | palm follows a symlink inside a source only when its real target stays inside the source. A skill cannot carry `~/.ssh/id_rsa` into `.claude/skills`. |
| Writes outside the scope | Every write and delete checks the real path. A path that resolves outside the project, or outside your home and harness homes with `-g`, is refused, naming the link. |
| Project scope in the wrong place | Your home directory, `~/.palm` and every harness home refuse project scope, so a forgotten `-g` never turns your dotfiles into a project. |
| Sources that overlap outputs | A source that contains, equals or sits inside an output folder or `.palm/assets` is refused on real paths, also when the output folder is a symlink into the source. |
| Deleting source files | palm never deletes or overwrites a path inside a declared source, `--force` included. |
| Two owners for one name | A second source cannot install an entity whose kind and name another source already installed, `--force` included. |
| Unresolvable commands | A hook or server command that names a script not in the source is refused, with the line. palm never merges a command it could not resolve. |
| Hidden Unicode | Bidirectional overrides and isolates, tag characters and rare variation selectors refuse the entity, including in a hook's scripts. There is no override. |
| Secrets from a source | A literal secret that arrives from a source is never written. palm writes `${NAME}` instead, and `--force` does not change that. A skill whose copied files hold a known token shape, or a high-entropy value in a configuration file, is refused. A high-entropy value in code warns. |
| Oversized skills | A skill copy leaves out harness folders, `.git`, `node_modules`, `.env*` and test folders, and one above 200 files or 5 MB needs `--force`. |
| Unsafe git transports | `ext::`, `fd::` and every other `<x>::` transport, a leading `-` and control characters in URLs. `http://` and `git://` warn. |
| Files it does not own | A file palm did not write that differs from the render stops the install until you pass `--force`. |
| Files you changed | palm compares each file with the lock's render hash before it overwrites or deletes it. |

## How palm runs git

git is the only program palm starts, apart from your pager.

- A clean environment from an allow list. Tokens and variables such as `GIT_DIR` never reach git, so a palm run from a git hook never touches the hook's repository.
- `protocol.ext.allow=never`, `protocol.fd.allow=never`, and `protocol.file.allow=never` except for local sources.
- `--` before every URL and ref, so a source cannot pass itself off as an option.
- `GIT_TERMINAL_PROMPT=0` and ssh in batch mode, so git never prompts.
- 120 seconds for network steps, 30 seconds for local ones.
- Inside a project, only read-only git commands.

## What palm never does

- It never runs what it installs.
- It never writes a secret that came from a source. A value you type becomes an environment reference unless you pass `--secrets literal`.
- It never writes a literal into a file inside a git worktree under `-g`, `--force` included, and warns before a project file git would commit.
- It never stores a secret value in the index or the lock. Both hold redacted hashes.
- It never sends telemetry, checks for updates or queries a registry.

## Deliberately not built

| Idea | Why not |
| --- | --- |
| A minimum-age or new-maintainer gate | git dates and authors are forgeable, so it would give false comfort. |
| Scanning prose for prompt injection | Unbounded false positives. The review diff is the honest tool. |
| Running scripts in a sandbox to inspect them | palm's promise is that it runs nothing it installs. |
| Signature verification | No source ships keys to verify against yet. |

## Report a vulnerability

Report a security problem in palm privately, through a [GitHub security advisory](https://github.com/PalionTech/palm/security/advisories/new).
Do not open a public issue for it.
The [security policy](https://github.com/PalionTech/palm/security/policy) lists what is in scope and how fast we respond.
The content of a source you chose is out of scope, so report a malicious skill to its repository's host.
