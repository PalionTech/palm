palm installs the files that configure AI coding agents.
You name a git repository and the skills, subagents, rules, hooks or MCP servers you want from it.
palm writes each one where every harness you use reads it.

```sh
npm install -g @paliontech/palm
palm install mattpocock/skills tdd
```

## One item, six formats

Coding agents read the same kinds of files: skills, subagents, instructions, hooks and MCP servers.
Each harness expects them in its own place and format.
A subagent is a Markdown file in `.claude/agents` for Claude Code.
Codex wants a TOML file in `.codex/agents`, and Copilot wants an `.agent.md` file in `.github/agents`.
An MCP server goes into `.mcp.json`, `.codex/config.toml`, `.vscode/mcp.json`, `.cursor/mcp.json`, `.gemini/settings.json` or `opencode.json`, and each spells an environment variable differently.

Copying by hand means one edit per harness for every change, and nothing records where a file came from.
palm reads a repository as its author published it, writes each item in each harness's format, and records the source commit and every file in `palm.lock.yaml`.

## What palm writes

- `palm.yaml` is the **manifest**. It lists the targets, each source with its version range, and what you took from it.
- `palm.lock.yaml` is the **lock**. It pins each source to a commit and records one hash per entry and target, plus every file palm wrote.
- Everything else is a **generated file**. You commit these too, so a teammate's clone and your CI hold the same bytes.

## When palm helps

| Situation | What palm does |
| --- | --- |
| You use two or more harnesses on one repository | One install writes the item for each of them, once per harness. |
| Your team shares skills, agents and MCP servers | The files are committed. A clone works without palm, and `palm check` proves it matches. |
| A plugin ships hooks | palm shows every command and script before it writes them, and pins your yes by hash. |
| An MCP server's README shows a JSON snippet | `palm install mcp --snippet -` reads it and writes it for every harness, with secrets as references. |
| You keep your own skills in the repository | `palm create skill <name>` writes a template into `./agent-kit` and installs it. Edits are live. |

## Eight verbs

| Verb | What it does |
| --- | --- |
| `palm init` | Write `palm.yaml` with the targets for this project. |
| `palm install` | List a source, install from it, or with no arguments make the disk match `palm.yaml` and the lock. |
| `palm remove` | Delete exactly the files and config entries an entity wrote. |
| `palm update` | Move sources to the newest commit their range allows, after showing a plan. |
| `palm check` | Read-only CI gate. Fails on any drift between `palm.yaml`, the lock, the files and in-repo sources. |
| `palm get` | List what is installed, the sources, or the targets. |
| `palm describe` | Show one entity, source, target, or the entity that wrote a file. |
| `palm create` | Write a template skill, agent, instruction or hook into your in-repo source. |

`palm migrate`, `palm completion` and `palm cache clean` are utilities. The [CLI reference](/palm/reference/cli/) covers all of them.
