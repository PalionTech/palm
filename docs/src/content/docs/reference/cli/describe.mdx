`palm describe` answers "what is this, where did it come from, and what did it write" for one thing.

```sh
palm describe <[kind:]name | path>
palm describe source <name>
palm describe target <target>
```

Alias: `palm info`.

| Command | What it shows |
| --- | --- |
| `palm describe tdd` | one installed entity |
| `palm describe hook:gh-cli` | the same, when a name means two kinds |
| `palm describe mcp docs` | an MCP server, with the block each harness received |
| `palm describe .claude/skills/tdd/SKILL.md` | the entity that wrote this file |
| `palm describe .mcp.json` | every entity with an entry merged into this file |
| `palm describe source mattpocock/skills` | a source: URL, ref, commit, detection rule, counts and index warnings |
| `palm describe target codex` | where each kind goes for Codex in this scope |

## Options

{/* cli-reference:options describe */}

| Argument | Meaning |
| --- | --- |
| `what` | [kind:]name, a path, source &lt;name&gt; or target &lt;id&gt; |

| Option | Meaning |
| --- | --- |
| `-s, --source <source>` | the entity from this source |

The [global options](/palm/reference/cli/#global-options) also apply.

{/* /cli-reference */}

## An entity

| Field | Shows |
| --- | --- |
| description | from the entity's frontmatter or manifest |
| source | the declared source, its ref, the resolved tag and the commit |
| path, version | where the entity lives in the source, and its version |
| selected by | `palm.yaml`, or `plugin:<name>` when a plugin selected it |
| files per harness | every generated path and merged entry, per target |
| notes | what install printed once: dropped fields, skipped targets, "from command", shared folders |
| program | for a hook or stdio server: every command, the hash, and whether it is trusted |
| scripts | the asset folder and its file count; for a skill, the scripts it cites |
| needs | for an MCP server: every variable, and whether it is set |

`palm describe mcp <name>` adds the rendered block for each harness, so you see exactly what Codex got in TOML.

## A path

Given a path, absolute, relative or starting with `~`, palm names the entity that wrote it.

| Match | Meaning |
| --- | --- |
| `file` | the entity wrote this file |
| `inside` | the path is a folder, and these entities wrote files inside it |
| `merged` | the file is shared, and these entities own entries in it, by JSON pointer, TOML table or block |

A path no entity wrote prints so and exits 1.

## A source or a target

`palm describe source <name>` shows the URL or path, ref, commit, root, layout, the scan rule that matched, the counts per kind and the index warnings. [Scanning](/palm/concepts/scanning/) shows an example.

`palm describe target <target>` renders a sample entity of every kind for that harness in the current scope, so the paths include any home-directory override you set.

## Reads and writes

`palm describe` reads `palm.yaml`, the lock and the cached index. It writes nothing.
It needs no network, except to index a declared source whose commit is not cached.

## Exit codes

| Code | When |
| --- | --- |
| `0` | The entity, path, source or target was found. |
| `1` | Nothing matches the name or path, or the name means two kinds. |
| `2` | No argument, or an unknown kind word. |
