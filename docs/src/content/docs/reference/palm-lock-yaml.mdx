`palm.lock.yaml` records every file and merged value palm wrote, the commit it came from and a hash of each file.
palm writes it on every install, update and uninstall. Commit it next to `palm.yaml`.

```sh
palm install skill grill-me --target claude,codex
palm install --frozen
```

| Key | Type | Meaning |
| --- | --- | --- |
| `version` | number | The lockfile format. palm writes `2`. |
| `targets` | list of target ids | The target set this scope was last installed against: `targets:` from `palm.yaml`, or from `config.yaml` in the global scope. A bare `palm install` removes only the targets that left this set since. Absent until an install records it. |
| `createdDirs` | list of paths | Harness folders palm created in this scope, such as `.claude`. An uninstall that leaves one empty removes it. Absent when there are none. |
| `entries` | list | One entry per installed entity in the scope. |

## Location

| Scope | File |
| --- | --- |
| project | `palm.lock.yaml` next to `palm.yaml` in the project root |
| global | `~/.palm/palm.lock.yaml`, or `$PALM_HOME/palm.lock.yaml` |

## Entry keys

palm writes the keys of an entry in this order and leaves out the ones that do not apply.

| Key | Type | Meaning |
| --- | --- | --- |
| `kind` | string | `skill`, `agent`, `instruction`, `command`, `hook`, `mcp` or `plugin`. |
| `name` | string | The entity name. For MCP servers, the key in the harness config. |
| `origin` | string | The origin alias, or `registry`, `adhoc` or `mine`. |
| `url` | string | Git origins: the clone URL. A machine without the alias recreates it from this. |
| `root` | string | Git origins: the folder in the repository that is the origin root. |
| `ref` | string | The tag or branch palm resolved. |
| `sha` | string | The commit. A bare `palm install` deploys exactly this commit. |
| `path` | string | Where the entity sits in the origin: a folder for skills and plugins, else a file. For registry servers, the registry name. |
| `contentHash` | string | `sha256:<hex>` of the entity's source. |
| `transform` | number | The version of palm's rendering the files were written with. `0` marks an entry read from version 1. |
| `targets` | list | The targets the entity was written to. |
| `files` | list of `{ path, hash }` | Every file palm wrote. See [files](#files). |
| `merged` | list of `{ file, pointer, value }` | Every value palm inserted into a shared file. See [merged](#merged). |
| `via` | string | `plugin:<name>` or `agent:<name>` for a dependency. Direct installs have none. |
| `deps` | list of `{ kind, name }` | Plugin and agent entries: the entities they declared. |

### `files`

`path` is relative to the project root in project scope, and absolute in global scope.
`hash` is `sha256:<hex>` of the file as palm wrote it, with text hashed using LF line ends.
Before palm overwrites or deletes a file, it compares the file on disk with this hash.
A file you changed is refused with `E_CONFLICT` unless you pass `--force`.
An empty hash means unknown, from version 1 or a dry run, and never counts as a change.

### `merged`

`file` is the shared file, such as `.mcp.json`, `.claude/settings.json` or `.codex/config.toml`.
`pointer` is a JSON pointer to the place palm inserted the value.
For a managed block in `AGENTS.md` or `GEMINI.md`, it is `block:<id>`.
`value` is the exact value palm inserted, so an uninstall removes that value and nothing else.
A secret is recorded as its `${NAME}` placeholder, never as its value.

## Determinism

The same install gives the same bytes on every machine:

- No timestamps.
- Entries sorted by kind (`skill`, `agent`, `instruction`, `command`, `hook`, `mcp`, `plugin`), then by name ignoring case, then by origin.
- Names and paths compared by code point, never by locale.
- Keys in a fixed order, `files` sorted by path, `targets` in the order `claude`, `codex`, `copilot`, `cursor`, `gemini`, `opencode`.
- Empty `merged` and `deps` lists left out.
- LF line ends. palm writes the file fresh each time, with a comment line at the top.

## Recorded truthfully

An entry lists only the targets and files that succeeded.
An entity whose every target failed keeps its previous entry, or has none.
palm saves the lockfile after every entity, so an interrupted install leaves a lockfile that matches the disk.

## Version 1

palm reads a version 1 lockfile and converts it in memory.
Version 1 has `installedAt` timestamps and `files` as plain paths.
The converted entries get an empty `hash` and `transform: 0`.
The next save writes version 2, and the first install re-renders every entry and records its hashes.

A lockfile with any other `version` fails with `E_PARSE` and the hint to upgrade palm.

## When the lockfile breaks

An entry without `kind`, `name` or `origin`, or a malformed `files` item, fails with `E_PARSE`.
Restore the file from version control, or delete it and run `palm install`.
After a merge conflict, resolve both sides, then run `palm install` so palm checks the result against the disk.
