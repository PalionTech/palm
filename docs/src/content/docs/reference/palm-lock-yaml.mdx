`palm.lock.yaml` records what each source resolved to and what palm wrote. palm writes it on `install`, `remove` and `update`, and you commit it with `palm.yaml` and the generated files.

<Capture name="c-lock" title="~/project" />

The lock is deterministic. Saving the same lock twice gives the same bytes, and a newcomer's lock for the same `palm.yaml` equals a veteran's.

## Top level

| Key | Meaning |
| --- | --- |
| `version` | `3`. Versions 1 and 2 come from palm 0.1, and only `palm migrate` reads them. |
| `sources` | one record per source, keyed by the name in `palm.yaml` |
| `entries` | one record per installed entity, sorted by kind, then name |

## Sources

| Key | Meaning |
| --- | --- |
| `url` | the clone URL of a git source |
| `root` | the folder inside the repository, when set |
| `ref` | the intent, copied from `palm.yaml` when it was resolved |
| `resolved` | the tag a range resolved to |
| `sha` | the resolved commit, the one a bare install uses |
| `path` | an in-repo source's project-relative path |
| `layout` | the layout in effect, so another machine rebuilds the same index from the commit alone |
| `descriptor` | the scan rule that produced the index: `descriptor`, `apm`, `marketplace`, `plugin-manifest` or `convention` |

An in-repo source has no commit and no source-wide hash.
Each of its entries carries a `content` hash over that entry's own files, and `palm check` compares entry by entry.
Two pull requests that change two different skills therefore touch two different lock lines.

## Entries

| Key | Meaning |
| --- | --- |
| `kind`, `name` | the entity |
| `source` | the source name, or `manifest` for an MCP server declared in `palm.yaml` |
| `path` | where the entity lives in the source |
| `via` | `plugin:<name>` when a plugin selected it |
| `content` | sha256 of the entity's content in the source; for an in-repo source, the signal that its files changed |
| `render` | one render hash per target: sha256 over the path, mode and content hash of every file the target writes, plus every fragment it merges |
| `files` | every path palm wrote for the entry, sorted, closure files included |
| `merged` | the fragments merged into shared files, as `{ file, at, id, key }` |
| `exec`, `trust` | the entry's programs and your consent; see below |
| `notes` | what install printed once: dropped fields, skipped targets, shared folders; `palm describe` shows them |
| `targets` | only when `palm.yaml` narrows the entry below the scope's set; a refused target never narrows it |
| `at` | the placement root from `palm.yaml`, stored for 0.3 |
| `deps` | plugin entries only: the members the plugin declared |

Two hashes per entry per target, never one per file, keep the lock short and let every machine compute the same values.

## Merged entries

A fragment in a shared file, such as a hook in `.claude/settings.json` or a server in `.mcp.json`, carries two identities.

| Key | Meaning |
| --- | --- |
| `file` | the shared file |
| `at` | a JSON pointer such as `/hooks/Stop`, a TOML table such as `/mcp_servers/docs`, or `block:<id>` for a Markdown block |
| `id` | palm's identity, `palm:<kind>:<name>:<n>` |
| `key` | what finds the fragment on disk: the object key, the block id, or a short hash of an array item's identity |

palm tells "changed" (found, different value) from "missing" (not found).
Removing one plugin therefore never takes another plugin's hook, even when both merged into the same array.

## Exec and trust

An entry with a hook or a stdio MCP server carries its programs.

```yaml title="palm.lock.yaml"
    exec:
      commands:
        - { id: Stop//-, command: 'bash "$CLAUDE_PROJECT_DIR"/agent-kit/hooks/quality.sh' }
      hash: sha256:5d41c3b0…
    trust: [sha256:5d41c3b0…]
```

| Key | Meaning |
| --- | --- |
| `exec.commands` | one line per command a harness runs: `<event>//<matcher or ->` for hooks, `stdio` for a server |
| `exec.closure` | the scripts the commands run and the files they read, with their count and tree hash; for an in-repo source, hashed where they sit, since they run in place |
| `exec.hash` | the program hash over the canonical commands, events, matchers, environment keys, working directory and the closure tree |
| `trust` | the hashes a person consented to; palm installs silently while `exec.hash` is among them |

The lock diff is the team's consent record, with readable commands and one hash line reviewed together.
An entry with a program and no `trust:`, or with an empty `render:`, fails `palm check`.
A hook you declined is not in the lock. It is an `exclude:` on the plugin entry in `palm.yaml`, where review sees it.

## What the lock never holds

No absolute path, home directory, hostname, timestamp, machine fact, per-file hash, created-folder list, top-level target list, secret value or merged value.
The value of a merged fragment is recomputed from the render, and a secret-shaped value appears only as a redacted hash.

## The global lock

`~/.palm/palm.lock.yaml` has the same shape.
Every path starts with a token: `<home>`, `<palm>`, `<agents>`, `<claude>`, `<codex>`, `<copilot>`, `<cursor>`, `<gemini>` or `<opencode>`.
The same lock works on machines whose harness homes differ, and `~/.palm/applied.yaml` records the real paths this machine holds.
