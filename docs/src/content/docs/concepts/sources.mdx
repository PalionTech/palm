A **source** is a git repository, optionally a folder inside it at a ref, or a directory inside your project.
palm installs entities from sources, and every source is declared in `palm.yaml`, so it is a dependency of the project and never a per-user setting.

<Capture name="a-sources" title="~/project" />

The first install from `mattpocock/skills` declared it in `palm.yaml` with a version range.
`palm get sources` shows each source with its range, the commit it resolved to and the number of entries taken from it.

## Forms a source takes

The first word after `palm install` is the source.

| You type | palm declares | Example |
| --- | --- | --- |
| `owner/repo` | a GitHub repository, keyed `owner/repo` | `palm install mattpocock/skills tdd` |
| `owner/repo/sub/dir` | the same repository with `root: sub/dir` | `palm install cursor/plugins/pstack comment-sicko` |
| `github:owner/repo` | the same as `owner/repo` | `palm install github:obra/superpowers --all` |
| an `https://`, `ssh://` or `user@host:path` URL | a named source with `url:` | `palm install https://gitlab.acme.com/platform/agent-kit.git reviewer` |
| any of these plus `#ref` | the source with that `ref:` | `palm install mattpocock/skills#v1.2.3 tdd` |
| `./dir` | an in-repo source, rendered from the working tree | `palm install ./agent-kit review` |
| a name already in `palm.yaml`, or its `alias` | that source | `palm install kit reviewer` |

palm also accepts `file://` URLs, and `http://` and `git://` with a warning.
It refuses every other scheme, `ext::` style transports and a leading `-`.
A local path outside the project is refused, because a teammate's clone would not have it.

## Declared on first use

palm writes a source to `palm.yaml` the first time you install something from it.
A repository you only list is fetched and indexed, and nothing is saved.

- GitHub shorthand is keyed by `owner/repo`.
- A URL is keyed by the repository name, or `owner-repo` when that name is taken. `--as <name>` picks the key yourself.
- A directory is keyed by its project-relative path, such as `./agent-kit`.

palm always writes the `ref:` it used, so the intent is visible in review.

| The repository has | palm writes | and prints |
| --- | --- | --- |
| a `#ref` you typed | that ref | nothing extra |
| semver tags | a caret range on the newest tag | `i ref ^1.2 saved to palm.yaml (latest tag v1.2.3)` |
| no tags | the default branch, by name | `i ref main saved to palm.yaml; edit ref: to pin a tag` |

Declaring the same URL under another name prints `~ source acme → kit (renamed)`.
A different ref for a declared source prints `~ source acme: ref ^1.2 → main` and needs a confirmation or `--yes`.

## Refs and ranges

`ref:` is the one place a version lives. It is a tag, a branch, a commit or a semver range.

| `ref:` | Resolves to |
| --- | --- |
| `v1.2.3` | that tag |
| `main` | the head of that branch when the source is first resolved or updated |
| `3f2a1c9` | that commit |
| `^1.2` | the highest tag from `1.2.0` up to, not including, `2.0.0` |
| `~1.2` | the highest `1.2.x` tag |
| `1.x`, `v1` | the highest `1.x` tag, unless a branch or tag has exactly that name |
| `">=1.2 <2"` | any range the semver package accepts |

A branch or tag named exactly like the range wins, such as a `2.x` maintenance branch or a moving `v1` tag.
Tags may carry a `v` prefix. Prereleases match only when the range names one.

The lock records the range, the tag it resolved to and the commit.
A bare `palm install` always uses the locked commit.
`palm update` moves the commit within the range, and `palm update --to <ref>` changes the range itself.

## In-repo sources

A directory inside the project, such as `./agent-kit`, is a source like any other.
palm renders it from the working tree, so the directory is the truth.

- The lock stores a tree hash of the directory instead of a commit.
- A bare `palm install` re-renders every entry whose files changed and reports `~ re-rendered`.
- `palm check` fails when the directory changed since the lock was written, and names the command that fixes it.
- Hook scripts run in place, from the directory, so a script edit is live at once.
- An in-repo source has no `ref:`. For a tagged checkout, use a `file://` URL instead.

`palm create` writes templates into `./agent-kit` and declares it for you. See [Publish your own source](/palm/guides/publish-your-own/).

## Aliases

The key is the source's name everywhere: in `palm.yaml`, in the lock, in `--allow-exec` keys and in messages.
A source may add an `alias:` to save typing.

```yaml title="palm.yaml"
sources:
  acme-kit:
    url: https://gitlab.acme.com/platform/agent-kit.git
    alias: kit
    agents: [reviewer]
```

`palm install kit tester` then installs from `acme-kit`.
Names and aliases are unique within one `palm.yaml`, ignoring case.

## What palm refuses

- A source that overlaps an output directory, such as `./.claude`. The error names both paths and suggests `./agent-kit`.
- A source missing on disk, or a renamed in-repo directory, on every command until you fix `palm.yaml`.
- A project source under `-g`. The global scope has its own sources in `~/.palm/palm.yaml`, and the error says so.

A marketplace or plugin manifest inside a source is only a hint for finding entities.
It never registers anything, and palm never fetches another repository on its own. [Scanning](/palm/concepts/scanning/) explains what palm reads.
