A **harness** is the program that runs a coding agent, such as Claude Code or Codex.
A **target** is palm's identifier for a harness, such as `claude` or `codex`.
Flags and config values use targets. Prose about the tools uses harnesses.

<Capture name="a-targets" title="~/project" />

The install wrote the skill for Claude Code and Codex, and saved `targets: [claude, codex]` to `palm.yaml`.
`palm get targets` shows the active targets and where the set came from.

## The six targets

| Target | Harness | Detected in a project by |
| --- | --- | --- |
| `claude` | Claude Code | `.claude/` or `CLAUDE.md` |
| `codex` | Codex | `.codex/` or `AGENTS.md` |
| `copilot` | GitHub Copilot | `.github/copilot-instructions.md`, `.github/agents/` or `.vscode/mcp.json` |
| `cursor` | Cursor | `.cursor/` |
| `gemini` | Gemini CLI | `.gemini/` or `GEMINI.md` |
| `opencode` | OpenCode | `.opencode/`, `opencode.json` or `opencode.jsonc` |

For the global scope, palm detects a harness by its home directory.
Those are `~/.claude`, `~/.codex`, `~/.copilot`, `~/.cursor`, `~/.gemini` and `~/.config/opencode`.

## How palm picks targets

palm takes the first of these that gives an answer.

1. The `--target` flag.
2. `targets:` in the project's `palm.yaml`.
3. `targets:` in `~/.palm/config.yaml`, your global default.
4. The harness markers in the table above.
5. A prompt, when a terminal is attached.

Without a terminal and without an answer, palm stops and suggests `--target claude,codex`.

## Saved targets

The first project install saves the resolved set to `palm.yaml` when it has no `targets:`, and prints one line that says so.
`palm init --target claude,codex` writes the list before you install anything, and changes it later.
For `-g`, set your default with `palm config set targets claude,codex`. A global install never writes it.

Commit `palm.yaml` with its `targets:`.
Every clone then installs for the same harnesses, whatever each machine detects.

A `--target` on one install applies to the entities you name and leaves the saved set alone.
palm prints a note when the flag differs from the saved set.
A bare `palm install` puts every entry on at least the saved targets and keeps targets a `--target` added.
When you remove a target from `targets:`, the next bare `palm install` deletes that harness's files and merged entries.

## Where one target writes

`palm describe target <id>` lists where each kind goes in the current scope.

<Capture name="a-describe-target" title="~/project" />

The paths come from a dry run of each kind, so they include any home-directory override you set.
Add `-g` to see the global paths.

## One shared skill folder

Codex, GitHub Copilot, Cursor, Gemini CLI and OpenCode all read skills from `.agents/skills`.
palm writes that folder once, however many of the five are active.
Claude Code reads only `.claude/skills`, so a skill for `claude` gets its own copy.

## What a harness does not support

Some harnesses have no place for a kind at one scope.

- Codex has no project-level prompts, so a project `command` skips `codex`.
- Copilot has no user-level prompt files, so a global `command` skips `copilot`.
- Cursor keeps user rules in its settings, so a global `instruction` skips `cursor`.
- OpenCode hooks are JavaScript plugins, so palm skips hooks for `opencode`.

palm says so in the install summary and writes nothing the harness would ignore.
The [targets matrix](/palm/reference/targets-matrix/) marks each combination.
