An **MCP server** entry tells a harness how to reach a Model Context Protocol server.
It is a command that starts the server (stdio), or a URL (HTTP).
palm merges the entry into each harness's config file and writes secrets as environment references.

No file holds the token, so you can commit all of them.

## Three sources

| Source | Command | Notes |
| --- | --- | --- |
| An origin | `palm install mcp github` | From an `.mcp.json` or `mcp.json` in a repository or plugin. Agents and plugins pull these in as dependencies. |
| The official MCP registry | `palm install mcp io.github.upstash/context7` | palm prefers the server's HTTP endpoint. Otherwise it runs the package with `npx -y`, `uvx` or `docker run`. |
| Ad hoc | `palm install mcp fs -- npx -y @modelcontextprotocol/server-filesystem .` | Everything after `--` is the command. Use `--url`, `--header` and `--env` for the other settings. |

A registry server's short name is its config key.
When two registry servers share a short name, the second one gets its namespace as a prefix, such as `b-mcp`.
palm records that key in `palm.yaml` and reuses it on every reinstall.

## One secret, six spellings

palm treats every `${VAR}` in an MCP server's `env`, `headers`, `url` or `args` as a secret.
Each harness spells an environment reference differently, and palm writes each spelling.

| Harness | File | `Authorization: Bearer ${DOCS_TOKEN}` becomes |
| --- | --- | --- |
| Claude Code | `.mcp.json` | `Bearer ${DOCS_TOKEN}` |
| Codex | `.codex/config.toml` | `bearer_token_env_var = "DOCS_TOKEN"` |
| GitHub Copilot | `.vscode/mcp.json` | `Bearer ${env:DOCS_TOKEN}` |
| Cursor | `.cursor/mcp.json` | `Bearer ${env:DOCS_TOKEN}` |
| Gemini CLI | `.gemini/settings.json` | `Bearer ${DOCS_TOKEN}` |
| OpenCode | `opencode.json` | `Bearer {env:DOCS_TOKEN}` |

These are two of the files from the session above.

```json title=".mcp.json"
{
  "mcpServers": {
    "docs": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${DOCS_TOKEN}"
      }
    }
  }
}
```

```toml title=".codex/config.toml"
[mcp_servers.docs]
url = "https://example.com/mcp"
bearer_token_env_var = "DOCS_TOKEN"
```

Codex has no `${VAR}` syntax in its config.
palm uses `bearer_token_env_var` for a bearer token, `env_http_headers` for other headers and `env_vars` for a stdio server's environment.
A placeholder inside `args` stays unexpanded for Codex, and the install summary says so.

## Secret policies

| Scope | Default policy | What palm writes |
| --- | --- | --- |
| project | `env-ref` | The harness's own reference. palm prints which variables to export. |
| global (`-g`) | `literal` | The value, from your environment or a masked prompt, into a user config file created with mode `0600`. |

The lockfile stores the `${VAR}` placeholder under both policies, never the value.
Change the policy for one command with `--secrets env-ref` or `--secrets literal`.
Change the default with `palm config set secrets.project` or `palm config set secrets.global`.

Under `literal`, a script without the variable set fails before palm writes anything, and names the variable.
Export it, or run the command the hint prints, which adds `--secrets env-ref`.

:::caution
`--secrets literal` in project scope writes the secret value into files you may commit.
Use it only for files that git ignores.
:::

## Optional secrets

A registry server can mark a secret as optional, and `${VAR:-default}` does the same in an ad hoc definition.
Claude Code refuses a config whose variable is unset and has no default.
palm therefore writes an optional secret as `${VAR:-}` for Claude Code.
Under `literal`, an optional secret you leave empty drops its header or variable.

Variables the harness fills in at run time, such as `CLAUDE_PLUGIN_ROOT`, `workspaceFolder` or `HOME`, are never secrets.
palm leaves them as written.

## HTTP servers and OAuth

An HTTP server without secrets gets its URL only.
The harness runs the OAuth sign-in on first connect, and palm stores no token.

## Stdio servers run on your machine

A stdio server is a command the harness starts with your permissions.
palm lists every stdio command before it writes the entry, and asks once.
A script passes `--yes` after a review, or `--dry-run` to see the list.

## Exact removal

palm records each merged entry in the lockfile as a file, a JSON pointer and the value it inserted.
`palm uninstall mcp docs` removes that value from each file and leaves your other servers alone.
It removes containers it emptied, and deletes a JSON file left as `{}`.
`palm find .mcp.json` lists every entity with an entry in that file.
