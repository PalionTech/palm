Your team's docs server needs a bearer token, and a search server needs an API key.
The six harnesses spell an environment reference in four different ways.
One pasted value in `.mcp.json` ends up in git history.
palm writes each harness's own reference and tells you which variables to export.

When you finish, every config file names the variable and none holds its value:

<Capture name="b-mcp-http" title="~/project" />

## Before you start

- A project with its targets set, for example `palm init --target claude,codex,copilot,cursor,gemini,opencode`.
- The token values, to export in the shell that starts each harness.

## Steps

<Steps>

1. Install a server from the MCP registry that needs a key.

   ```sh
   palm install mcp io.github.brave/brave-search-mcp-server
   ```

   The registry entry marks `BRAVE_API_KEY` as required and secret.
   The server runs through `npx` on your machine, so palm lists that command and asks once before it writes anything.
   palm then prints `export BRAVE_API_KEY before starting the harness`.
   This step reads the live registry, so it has no recorded session. These details were checked on 2026-09-28.

2. Install an HTTP server that sends a token header.

   ```sh
   palm install mcp docs --url https://docs.example.com/mcp --header 'Authorization=Bearer ${DOCS_TOKEN}'
   ```

   Single quotes keep your shell from expanding `${DOCS_TOKEN}`.
   palm reads `${NAME}` in a header, an environment value, a URL or an argument as a secret.

3. Read what each harness received. The session at the top shows the lines:

   | Harness | File | Header value, or setting |
   | --- | --- | --- |
   | Claude Code | `.mcp.json` | `Bearer ${DOCS_TOKEN}` |
   | Codex | `.codex/config.toml` | `bearer_token_env_var = "DOCS_TOKEN"` |
   | GitHub Copilot | `.vscode/mcp.json` | `Bearer ${env:DOCS_TOKEN}` |
   | Cursor | `.cursor/mcp.json` | `Bearer ${env:DOCS_TOKEN}` |
   | Gemini CLI | `.gemini/settings.json` | `Bearer ${DOCS_TOKEN}` |
   | OpenCode | `opencode.json` | `Bearer {env:DOCS_TOKEN}` |

   For the registry server's `BRAVE_API_KEY`, `.mcp.json` gets `"BRAVE_API_KEY": "${BRAVE_API_KEY}"` and Codex gets `env_vars = [ "BRAVE_API_KEY" ]`.
   Codex takes any header other than a bearer token through `env_http_headers`.
   An optional secret becomes `${NAME:-}` for Claude Code, which refuses a config with an unset variable.

4. Export the variables before you start a harness.

   ```sh
   export DOCS_TOKEN=<token>
   export BRAVE_API_KEY=<key>
   ```

   Put them in your shell profile or a secrets manager, never in a file inside the repository.

</Steps>

### Secrets in arguments and Codex

Codex does not expand variables in `args` or in a URL.
palm writes the placeholder as it is and says so:

<Capture name="b-mcp-args" title="~/project" />

Move the value into an environment variable with `--env`, or install that server with `--secrets literal`.

### Literal values

`--secrets literal` writes the value itself instead of a reference.
palm takes it from your environment, or asks for it without echoing it when a terminal is attached.
The global scope (`-g`) uses `literal` by default and creates the user-level config files with mode 0600.

:::caution
In a project, `--secrets literal` puts the token into files you would normally commit.
Keep those files out of git, or use the default `env-ref` policy.
:::

`palm.yaml` and `palm.lock.yaml` never store a value, under either policy.
They keep the `${NAME}` placeholder.

## Check the result

Stage everything and search the staged files for the token value:

```sh
git add -A
git grep -F "$DOCS_TOKEN"
```

No output means no staged file holds the value.
`git grep` exits 1 in that case.
