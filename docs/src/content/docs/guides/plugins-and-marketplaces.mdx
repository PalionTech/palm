Claude Code, Cursor and Codex plugins ship in repositories, often listed in a `marketplace.json`.
Each harness's own installer serves only that harness.
palm reads the same repository and installs a plugin's skills, agents (subagents), hooks and MCP servers for all your harnesses at once.

When you finish, one plugin is installed for Claude Code and Codex, its hook script is committed, and one skill is excluded for the team:

<CaptureTree name="b-plugin" depth={4} />

The session on this page ran against palm's fixture that mirrors `obra/superpowers`.

## Before you start

- A project with its targets set, for example `palm init --target claude,codex`.
- The repository that holds the plugin or the marketplace.

## Steps

<Steps>

1. See what the repository offers.

   ```sh
   palm install anthropics/claude-plugins-official
   ```

   <Capture name="a-entities" title="~/project" />

   A marketplace lists plugins. palm indexes each plugin kept in the same repository and lists its members.
   A plugin hosted elsewhere gets a warning with the `palm install` line that declares its repository as a source of its own. palm never fetches it by itself.

2. Install the plugin.

   ```sh
   palm install obra/superpowers plugin:superpowers
   ```

   `plugin:` selects every member. palm records `plugins: [superpowers]` in `palm.yaml`, and each member's lock entry says `via: plugin:superpowers`.
   To take only some members, name them instead, or add `only:` to the plugin entry.

3. Review the hook, and consent.

   A plugin's hook runs a program on every matching event.
   palm shows the command, the targets and every script, and asks. Without a terminal it stops and prints the `--allow-exec` line.

   <Capture name="b-plugin" title="~/project" />

4. Drop a member for everyone.

   ```sh
   palm remove obra/superpowers brainstorming --exclude
   ```

   Removing a plugin member by name alone stops and names both choices.
   `--exclude` adds `skill:brainstorming` to the plugin's `exclude:` list, so a teammate's bare install and the next update keep it out.

</Steps>

:::caution
A hook runs its command on every matching event, such as each session start.
Press `v` at the prompt to read every script before you answer. The default is no.
:::

## Where hook scripts go

palm copies what a hook runs into `.palm/assets/<source>/<hook>/`: the folder that holds the hook definition, plus every file a command names.
It never copies `SKILL.md`, `AGENTS.md` or plugin manifests, so no harness finds a second copy of anything there.
Commands point at the copy through each harness's project directory variable, such as `"$CLAUDE_PROJECT_DIR"`, never through an absolute path.
You commit the folder, so a clone without palm has working hooks.

## Harnesses without plugins

Gemini CLI and OpenCode get a plugin's members as loose files.
OpenCode has no declarative hooks, so palm skips a plugin's hooks there, says so, and installs the rest.

## Check the result

```sh
palm get
palm remove obra/superpowers plugin:superpowers
```

`palm get` shows each member with `plugin:superpowers` in the `via` column.
`palm remove ... plugin:superpowers` removes every member, the merged hook entries and the asset folder.
A member that another installed plugin also declares stays, and palm says which command removes both.
