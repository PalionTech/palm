You start a service and want your agents to test first, review Python Agent SDK code and read your internal docs.
Four commands give Claude Code and Codex the same setup, and one commit gives it to everyone else.

When you finish, these files exist and all of them are committed:

## Before you start

- palm is installed, and the project is a git repository.
- You know which harnesses the team uses. This guide uses Claude Code and Codex.

## Steps

<Steps>

1. Declare the targets.

   ```sh
   palm init --target claude,codex
   ```

   Committing `targets:` means every clone installs for the same harnesses, whatever each laptop has.

2. Install two skills from one repository.

   ```sh
   palm install mattpocock/skills tdd grill-me
   ```

   Name as many entities as you want after the source.
   Not sure what a repository offers? Run `palm install mattpocock/skills` first. It lists everything and writes nothing.

3. Install an agent from another repository.

   ```sh
   palm install anthropics/claude-plugins-official agent-sdk-verifier-py
   ```

   The agent names a skill and an MCP server it likes to use. palm prints the command for them and installs only what you named.

4. Add the docs MCP server.

   ```sh
   palm install mcp docs --url https://docs.example.com/mcp --header 'Authorization=Bearer ${DOCS_TOKEN}'
   ```

   The token stays in your environment. Each harness gets its own spelling of the reference.

   <Capture name="b-new-project" title="~/project" />

5. Check and commit.

   ```sh
   palm check
   git add -A
   git commit -m "Add the agent setup"
   ```

</Steps>

## Check the result

<Capture name="b-new-project-result" title="~/project" />

`palm.yaml` reads like a dependency list: two sources with their ranges, what you took from each, and one hand-declared server.
`palm check` passes with one warning, because `DOCS_TOKEN` is not set in this shell.
Export it before you start Claude Code or Codex, and the warning goes away.
