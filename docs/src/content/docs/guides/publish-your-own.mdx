You wrote a skill that turns merged pull requests into release notes, and the next service wants it too.
Start it inside the project with `palm create`, where every edit is live.
When it proves itself, push the folder as its own repository, tag it, and any project installs it by name.

When you finish, a teammate in another project installs your skill from its tag:

<Capture name="b-publish-teammate" title="teammate: ~/other-project" />

## Before you start

- A project with targets set, for example `palm init --target claude,codex`.
- An empty repository on GitHub, or on any git host, for step 4.

## Steps

<Steps>

1. Create the skill.

   ```sh
   palm create skill release-notes --description 'Write release notes from the pull requests merged since the last tag.'
   ```

   palm writes a template into `./agent-kit`, declares `./agent-kit` in `palm.yaml` and installs the skill. It asks nothing and opens no editor.

   | Kind | Template |
   | --- | --- |
   | `skill` | `agent-kit/skills/<name>/SKILL.md` |
   | `agent` | `agent-kit/agents/<name>.md` |
   | `instruction` | `agent-kit/instructions/<name>.md` |
   | `hook` | `agent-kit/hooks/<name>/hooks.json` with an example script |

   `--in <dir>` picks another folder, and a `layout:` on that source decides where the template goes.
   A file that already exists, or a name the source or another source already has, stops with `E_CONFLICT` before palm writes anything.

2. Write the skill, and let palm follow.

   <Capture name="b-create" title="~/project" />

   The in-repo source is the truth. After an edit, `palm check` fails until you run `palm install`, which re-renders the harness copies.
   Commit `agent-kit/`, the lock and the generated files together.

3. Give it a shape other repositories use.

   palm reads a repository without any palm file, so follow the conventions every harness knows.

   | Put | Where |
   | --- | --- |
   | skills | `skills/<name>/SKILL.md` with `name` and `description` frontmatter |
   | agents | `agents/<name>.md` with `name` and `description` frontmatter |
   | instructions | `instructions/<name>.md`, `rules/<name>.md`, `rules/<name>.mdc` or `<name>.instructions.md` |
   | hooks | `hooks/hooks.json`, with scripts next to it referenced as `${CLAUDE_PLUGIN_ROOT}/hooks/<file>` |
   | MCP servers | `.mcp.json` with `mcpServers` |
   | a version | a semver tag, or `metadata.version` in the frontmatter |

   A `.claude-plugin/plugin.json` is optional. It lets people select your members as one plugin.

4. Copy the folder into its own repository and tag it.

   ```sh
   cp -R agent-kit ~/src/agent-kit
   cd ~/src/agent-kit
   git init -b main
   git add -A
   git commit -m "Add the release-notes skill"
   git remote add github git@github.com:acme/agent-kit.git
   git push -u github main
   git tag v1.0.0
   git push github v1.0.0
   ```

   An undeclared source resolves to its newest tag, and palm writes `ref: ^1.0` for the people who install it.
   Commits after `v1.0.0` reach them only when you push the next tag and they run `palm update`.

5. Switch your own project to the published source.

   ```sh
   palm remove ./agent-kit release-notes
   palm install acme/agent-kit release-notes
   git rm -r agent-kit
   ```

   `./agent-kit` had no entries left, so palm dropped it from `palm.yaml`. Commit the result.

</Steps>

## Check the result

In another project, a teammate runs one command, as in the session at the top.
`palm get` shows your tag in the `ref` column.

To publish a change, commit it, tag `v1.1.0` and push the tag.
Each project then runs `palm update acme/agent-kit`, reviews the plan and commits.

## What palm refuses from a source

- A hook command that names a script the repository does not have. Keep scripts inside the repository and reference them relative to the hook file or `${CLAUDE_PLUGIN_ROOT}`.
- Hidden Unicode such as bidi overrides or tag characters, in any file of an entity.
- A literal secret in an MCP config or hook command. Write `${NAME}` instead. A skill that carries one in any of its files is refused.
- A skill folder above 200 files or 5 MB, unless the person installing passes `--force`. A root `SKILL.md` makes the whole repository the skill, so keep skills in `skills/<name>/`.
- A symlink that leaves the repository.

palm also warns when a hook script reads a file it cannot resolve.
Refer to such a file by a literal path, such as `"$(dirname "$0")/../skills/x/SKILL.md"`, so palm copies it with the script.
