A reviewer agent (subagent) is only useful with the skill and the MCP server it calls.
If a teammate installs the agent alone, it fails at its first tool call.
palm reads the skills and MCP servers an agent file names as dependencies, so one install brings all three.

When you finish, one command installs the agent, its skill and its MCP server:

The sessions on this page ran against a palm test fixture that mirrors `anthropics/claude-plugins-official`.
It provides the skill `sdk-helper` and the MCP server `context7`.

## Before you start

- A terminal: `palm create` is an interactive wizard.
- Origins that hold the skills and MCP servers the agent will use. The MCP registry works too.

## Steps

<Steps>

1. Start the wizard.

   ```sh
   palm create agent sdk-reviewer
   ```

   | Prompt | What it offers |
   | --- | --- |
   | Agent name | a slug, prefilled from the command |
   | When should the main agent delegate to it? | free text: the agent's description |
   | Model | `inherit`, `opus`, `sonnet`, `haiku` or a custom id |
   | Tools | Claude Code tool names; select none to inherit all tools |
   | Skills this agent uses | installed skills and every skill your origins hold, with a search entry |
   | MCP servers this agent uses | installed and indexed servers, plus a search of the MCP registry |
   | Instructions to install alongside | shown only when your origins hold instructions |
   | System prompt | `$VISUAL` or `$EDITOR` when set, otherwise a text prompt |

   Then palm asks whether to install the agent now. The default is yes.

2. Read the file the wizard wrote.

   ```md title="~/.palm/mine/agents/sdk-reviewer.md"
   ---
   name: sdk-reviewer
   description: Use after changes to an Agent SDK app. Reviews the code and runs the tests.
   model: sonnet
   tools: Read, Grep
   skills:
     - sdk-helper
   mcpServers:
     - context7
   ---

   You review Agent SDK apps. Run the tests, then report failures first.
   ```

   `skills:` and `mcpServers:` are Claude Code frontmatter keys, and palm reads them as dependencies.
   A third key, `instructions:`, lists `name@origin` instructions; only palm reads it, and no harness receives it.
   Any agent file in any origin works the same way, whether the wizard wrote it or you did.

3. Install the agent, if you told the wizard not to.

   ```sh
   palm install agent sdk-reviewer@mine
   ```

   palm looks for each dependency in three places, and the first match wins:

   - the agent's own origin
   - the origin the dependency came from last time
   - all origins

   When several origins still match, palm shows a picker; without a terminal it stops with `E_AMBIGUOUS`.

4. Ask palm why an entity is installed.

   ```sh
   palm why mcp context7
   ```

   `palm why` prints who installed the entity, the chain up to `palm.yaml`, and every entity that still needs it.

5. Keep a dependency you use on its own, then remove the agent.

   ```sh
   palm install skill sdk-helper
   palm uninstall agent sdk-reviewer
   ```

   Installing `sdk-helper` by name adds it to `palm.yaml`, so it no longer depends on the agent.
   The uninstall removes the agent and `context7`, and keeps `sdk-helper`.

</Steps>

## Check the result

```sh
palm get
```

Only `sdk-helper` is left, with no `via`.
A dependency stays while `palm.yaml` lists it or another installed plugin or agent declares it.
