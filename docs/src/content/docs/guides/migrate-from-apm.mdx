Your project installs agent files with Microsoft APM from an `apm.yml`.
palm reads the same git repositories, APM packages included, and writes each harness's own files at install time.
Each dependency becomes a source in `palm.yaml`, and the files APM already wrote stay byte for byte where they are.

When you finish, an APM package's skill, prompt, agent (subagent), instruction and hook sit in each harness's own folder:

<CaptureTree name="b-apm" depth={3} />

The session on this page ran against palm's APM test fixture, a package with `apm.yml` and an `.apm/` folder.

## Before you start

- Commit the current state, so `git diff` shows every change palm makes.
- palm, git and Node 22 or later.

## How the two map

| APM | palm |
| --- | --- |
| `apm.yml` | `palm.yaml` |
| `apm.lock.yaml` | `palm.lock.yaml` |
| `apm_modules/` in each project | `~/.palm/cache/`, shared by all your projects |
| a package in `dependencies.apm` | a source, then the entities you want from it, or `--all` |
| an entry in `dependencies.mcp` | an `mcp:` entry, from the server's README snippet |
| compiled `AGENTS.md`, `CLAUDE.md` and `GEMINI.md` | one native file per entity and harness; managed blocks only in `AGENTS.md` and `GEMINI.md` |
| `executables:` approval | consent pinned by hash in `palm.lock.yaml` |

| APM command | palm command |
| --- | --- |
| `apm init` | `palm init` |
| `apm install` | `palm install` |
| `apm install <package>` | `palm install <owner/repo> <names>` or `palm install <owner/repo> --all` |
| `apm install --frozen` | `palm check` |
| `apm uninstall <package>` | `palm remove <source> <names>` |
| `apm update` | `palm update` |
| `apm outdated` | `palm update --dry-run` |
| `apm deps list` | `palm get` |
| `apm audit` | `palm check` |
| `apm compile` | none: palm writes native files when it installs |

## Steps

<Steps>

1. List what `apm.yml` installs. Take this file as the example.

   ```yaml title="apm.yml"
   name: my-service
   version: 1.0.0
   dependencies:
     apm:
       - acme/standards#v1.0.0
       - cursor/plugins/pstack
     mcp:
       - io.github.github/github-mcp-server
   ```

2. Choose the harnesses.

   ```sh
   palm init --target claude,copilot
   ```

   Use the harnesses from APM's `targets:` if you set it, or the ones your team runs.
   palm notices the `apm.yml` and prints one hint: an import command for it arrives in palm 0.3. Until then, these steps do the job.

3. Install each package.

   ```sh
   palm install acme/standards
   palm install acme/standards --all
   ```

   The first command shows what the package holds. The second installs everything except programs.
   A file APM already wrote that matches palm's output is adopted without a change.

4. Install the package's hook after you read it.

   ```sh
   palm install acme/standards format-on-save
   ```

   <Capture name="b-apm" title="~/project" />

   Without a terminal palm stops and prints the `--allow-exec` line. On a terminal it shows the same review and asks.

5. Take single entities where APM installed a whole folder.

   ```sh
   palm install cursor/plugins/pstack comment-sicko poteto-agent
   ```

6. Add the MCP servers from `dependencies.mcp`.

   palm has no registry client. Copy the JSON snippet from the server's README and pipe it in.

   ```sh
   pbpaste | palm install mcp --snippet -
   ```

   [Add MCP servers](/palm/guides/mcp-servers/) covers snippets, flags and secrets.

7. Remove APM's own files, then commit.

   ```sh
   rm apm.yml apm.lock.yaml
   rm -r apm_modules
   git add -A
   git commit -m "Install agent files with palm"
   palm check
   ```

   Delete the context files `apm compile` wrote, such as a root `AGENTS.md`, unless you edit them by hand.

</Steps>

palm does not follow `dependencies:` inside a package's own `apm.yml`.
It lists them once as a warning, with the command for each, and installs nothing you did not name.

## Check the result

```sh
palm get
palm check
```

`palm get` lists each entity with its source and targets.
`palm check` exits 0 when `palm.yaml`, the lock and the files agree.
