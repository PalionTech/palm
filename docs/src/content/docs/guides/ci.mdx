A teammate edits a skill in `.claude/` by hand, or adds an entry to `palm.yaml` without running palm.
Review misses it, and the harnesses on each laptop drift apart.
One CI step, `palm check`, catches both, never prompts and never writes.

When you finish, CI passes on a clean branch and fails on an edited file, with the fix on the line:

<Capture name="b-ci-check" title="CI: ~/project" />

## Before you start

- `palm.yaml`, `palm.lock.yaml` and the generated files are committed. See [Share a team baseline](/palm/guides/team-baseline/).
- CI can reach the sources over git. Private sources need a deploy key or token in the runner, as for any git dependency.

## Steps

<Steps>

1. Add the job.

   ```yaml title=".github/workflows/agents.yml"
   name: agent setup
   on: pull_request
   jobs:
     palm:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-node@v4
           with:
             node-version: 22
         - run: npm install -g @paliontech/palm
         - run: palm check
   ```

   `palm check` exits 1 when any check fails. Warnings alone exit 0.

2. Read the report when it fails.

   Each check prints one line, `✓` or `x`. Then comes one line per problem, ending in the command that fixes it.
   Run that command on your machine, review the diff, and commit.

3. Use JSON for anything that parses the result.

   ```sh
   palm check --json
   ```

   stdout holds one document: `{ ok, checks: [{ id, label, status, problems: [{ entity, file, message, fix }] }], warnings }`.

</Steps>

## What palm check covers

| Check | Fails when | Fix |
| --- | --- | --- |
| `manifest-lock` | an entry of `palm.yaml` has no lock entry, or the reverse; a `ref:` differs from the lock; a plugin filter names nothing | `palm install` |
| `lock-disk` | a generated file is missing or differs from the render; a merged entry is missing or changed | `palm install`, or `palm install <source> <name> --force` for an edited file |
| `local-sources` | an in-repo source changed since the lock was written | `palm install`, then commit `palm.lock.yaml` |
| `exec-trusted` | a hook or stdio server has no trusted hash, or a merged command differs from the lock | `palm install --allow-exec <key>=<hash>` |
| `hook-scripts` | a hook command names a script that is missing or not executable | `palm install` |
| `secrets` | a tracked or world-readable generated file holds a literal secret | fix the source, then `palm install <source> <name> --force` |
| `git-ignored` | an output directory or `.palm/assets` is ignored by git, so teammates never get the files | edit `.gitignore` |
| `sources-declared` | a lock source is missing from `palm.yaml`, or an in-repo source is missing on disk | `palm install`, or restore the directory |
| `links` | an output path resolves outside the project, or a source overlaps an output directory | move the source |
| `hidden-unicode` | a generated file holds a bidi override, a tag character or a rare variation selector | fix the source, then `palm install --force` |
| `double-load` | warning only: a harness would load one entity twice | palm 0.3 carrier rule |
| `block-size` | warning above 24 KiB of `AGENTS.md` or `GEMINI.md` blocks; failure above the harness's cap | move entries with `at:` in palm 0.3 |

`palm check` also lists every environment variable the installed MCP servers need, and warns when one is not set.
Checks that need git are listed as `skipped (not a git repository)` outside a repository.
Its only network access is fetching a locked commit that is not in the cache, so a cache between runs makes it offline.

## Programs in CI

A trusted hook installs in CI without a flag, because its hash is in the lock.
A new or changed one stops a bare install with `E_UNTRUSTED_EXEC`, and the error prints the line that consents.

<Capture name="b-ci-errors" title="CI: ~/project" />

Do not paste that `--allow-exec` line into a pipeline.
Review the program on your machine, where palm shows the scripts, and commit the lock with its new `trust:` hash.
From then on CI replays it silently, and any later change fails CI again until someone reviews it.

## Scripts that call palm

| palm would ask about | Without a terminal |
| --- | --- |
| running a hook or stdio MCP server | `E_UNTRUSTED_EXEC`, naming the `--allow-exec` line |
| applying an update plan | `E_NON_INTERACTIVE`, naming `palm update ... --yes` |
| cleaning the cache | `E_NON_INTERACTIVE`, naming `palm cache clean --yes` |
| a secret value under `--secrets literal` | `E_NON_INTERACTIVE`, naming `--secrets env-ref` |

`--yes` accepts every prompt except consent.
With `--json`, stdout holds exactly one JSON document, and an error is `{ "error": { "code", "message", "hint" }, "warnings": [] }`.
[Exit codes and errors](/palm/reference/exit-codes/) lists every code.
