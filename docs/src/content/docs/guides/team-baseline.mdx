Your platform team keeps its skills, agents and rules in `acme/agent-kit`.
Every service should have the same set, at the same version, for Claude Code and Codex.
One person sets it up once. Everyone else clones, and it works.

When you finish, a teammate's fresh clone passes `palm check` without a single palm command before it:

<Capture name="b-team-clone" title="teammate: ~/teammate" />

## Before you start

- The team's repository is reachable over git from every laptop and from CI.
- The project has `targets:` in `palm.yaml`, from `palm init --target claude,codex`.

## Set it up once

<Steps>

1. Install the team's entities by name.

   ```sh
   palm install acme/agent-kit ci-watch ci-watcher typescript
   ```

   palm declares `acme/agent-kit` in `palm.yaml` with a range on its newest tag, so later releases within `1.x` arrive through `palm update`.

2. Commit everything palm wrote, in one commit.

   <Capture name="b-team-setup" title="~/project" />

   The commit holds `palm.yaml`, the lock and every generated file.
   Reviewers see the skill text, the agent and the rule block in `AGENTS.md`, exactly as the harnesses will read them.

</Steps>

## What a teammate does

Nothing palm-specific. `git clone` delivers the files, and the harnesses read them.

palm is only needed to change the setup, and to prove it in CI.
A bare `palm install` on the clone counts every entry as unchanged and writes nothing.
If a hook is part of the baseline, the lock already holds the team's consent, so the clone installs it silently. [Consent](/palm/concepts/consent/) explains the hash that makes this safe.

## Take an update

The team tags `v1.1.0` of `acme/agent-kit`.
One person moves the project to it and opens a pull request.

<Capture name="b-team-update" title="~/project" />

`--dry-run` prints the plan and writes nothing.
`--yes` applies it without a prompt, and palm prints the diff stat.
The pull request shows the new skill text and the moved commit in the lock, and review decides.

The plan lists every entry of a source whose commit moves, including those whose files stay the same, so review sees each re-pin.
For a source pinned to an exact tag, the plan prints the latest tag, so a pin never hides a newer release.

A changed or new hook is never covered by `--yes`. It needs a fresh consent, shown with `d` as a diff against what the team trusted.
A hook or MCP server that a plugin starts to ship appears as `i new program available`, and nothing installs it until someone names it.

To leave the range, move it explicitly.

```sh
palm update acme/agent-kit --to ^2
```

## Remove something for everyone

<Capture name="b-team-remove" title="~/project" />

The removal is two deleted files and two edited ones.
Commit them, and every teammate's next `git pull` removes the agent. No one has to run palm.

## Personal additions

A teammate who wants an extra skill only for themselves installs it with `-g`, into their home directory.

```sh
palm install mattpocock/skills tdd -g
```

palm cannot switch off a committed entry for one person, because git tracks the file.
Use the harness's own switch instead, such as `.claude/settings.local.json` for Claude Code or a `[[skills.config]]` entry in `~/.codex/config.toml` for Codex.
Removing the entry with `palm remove` removes it for the whole team.
palm 0.3 adds `palm.local.yaml` for personal targets, sources and entries in one checkout, ignored by git, and per-person disable with it.
`--local` prints that and changes nothing until then.

## Protect the files that run programs

The lock records that someone consented to a hook's hash, not who did.
Make review of those files mandatory with a `CODEOWNERS` file, so a consent always passes through someone you chose.

```text title=".github/CODEOWNERS"
palm.lock.yaml            @acme/platform
.palm/assets/**           @acme/platform
.claude/settings.json     @acme/platform
.codex/hooks.json         @acme/platform
.github/hooks/            @acme/platform
.cursor/hooks.json        @acme/platform
.gemini/settings.json     @acme/platform
agent-kit/                @acme/platform
```

List the hook files of your targets only, and every in-repo source, such as `agent-kit/`.
A change to a hook's script, its command or its `trust:` hash then needs that team's approval.
