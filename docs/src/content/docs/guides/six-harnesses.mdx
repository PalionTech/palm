On many teams one developer uses Claude Code, another uses Cursor, and a CI job runs Codex.
Each harness wants the same agent (subagent) in a different folder and format.
palm writes all six from one command, records every file in one lock, and tells you what each harness could not take.

When you finish, the agent exists once per harness format and the skill twice:

<CaptureTree name="b-six-install" depth={3} />

The skill appears twice because Claude Code reads `.claude/skills`, which Cursor reads too, and the other four share `.agents/skills`.
The sessions on this page ran against palm's fixture that mirrors `anthropics/claude-plugins-official`.

## Before you start

- The project is a git repository.
- You accept that the Gemini CLI and OpenCode placements are unverified. They follow each harness's documentation and source, checked on 2026-09-28, and have not run against a live CLI in palm's tests yet.

## Steps

<Steps>

1. Declare all six targets.

   ```sh
   palm init --target claude,codex,copilot,cursor,gemini,opencode
   ```

2. Install the agent and the skill it uses.

   ```sh
   palm install anthropics/claude-plugins-official agent-sdk-verifier-py sdk-helper
   ```

   <Capture name="b-six-install" title="~/project" />

   Each `i` line names what one harness has no place for, such as a model field for Codex or an argument restriction for Copilot.
   palm records the same notes in the lock, and `palm describe agent-sdk-verifier-py` shows them later.

3. Compare the formats palm wrote.

   <Capture name="b-six-files" title="~/project" />

   | Harness | File | What palm changes |
   | --- | --- | --- |
   | Claude Code | `.claude/agents/<name>.md` | nothing: this is the source format |
   | Codex | `.codex/agents/<name>.toml` | TOML with `name`, `description` and `developer_instructions` |
   | GitHub Copilot | `.github/agents/<name>.agent.md` | Copilot tool names such as `read` and `execute`, MCP servers as `context7/*` |
   | Cursor | `.cursor/agents/<name>.md` | the tool list maps to `readonly` |
   | Gemini CLI | `.gemini/agents/<name>.md` | strict frontmatter with `kind: local` and Gemini tool names |
   | OpenCode | `.opencode/agents/<name>.md` | `mode: subagent` and a `permission` map that denies what the tool list leaves out |

4. Install kinds that some harnesses cannot hold.

   ```sh
   palm install anthropics/claude-plugins-official new-sdk-app
   palm install anthropics/claude-plugins-official hook:agent-sdk-dev --dry-run
   ```

   <Capture name="b-six-skips" title="~/project" />

   The command file installs as a skill everywhere, with a note about `$ARGUMENTS`.
   The hook lands in five harnesses. OpenCode has no declarative hooks, so palm skips it there and says so.

</Steps>

These are the combinations palm skips.

| Kind | Harness | Scope | Why |
| --- | --- | --- | --- |
| hook | OpenCode | both | OpenCode hooks are JavaScript plugins |
| instruction | Cursor | global | Cursor keeps user rules in its settings |

`palm describe target <target>` prints where each kind goes for one harness, skips included.

```sh
palm describe target opencode
```

## One entity, one carrier

Several harnesses read the same files, and palm keeps each entity loaded once per harness.
With `claude` and `cursor`, a skill lives only in `.claude/skills`, because Cursor reads it there.
Codex reads instructions from `AGENTS.md`, which Cursor, OpenCode and Copilot also read.
palm 0.2 still writes Cursor's own `.cursor/rules` file too, and `palm check` warns about the double load. palm 0.3 records one carrier per harness and drops the second copy.

## Check the result

```sh
palm describe agent-sdk-verifier-py
palm check
```

`palm describe` lists the file each target received and every note palm recorded.
