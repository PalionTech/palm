You publish skills, agents (subagents) or a plugin and want people on every harness to install them.
palm reads a repository as it is published, so you add no palm-specific file.
A few conventions decide whether each entity gets the name and version you meant.

When you finish, adding your repository prints its contents and no warnings:

<Capture name="b-author-clean" title="~/project" />

The sessions on this page ran against palm's test fixtures, which mirror `obra/superpowers` and `cursor/plugins`.

## Before you start

- A local clone of your repository.
- palm, to test it the way your users will.

## Steps

<Steps>

1. Put each entity where palm looks for it.

   | Kind | palm finds it at |
   | --- | --- |
   | skill | a folder with `SKILL.md`, up to five levels deep; a root `SKILL.md` makes the repository one skill |
   | agent | `agents/**/*.md` or `**/*.agent.md`, with `name` and `description` in the frontmatter |
   | command | `commands/*.md`, `commands/*.toml` or `prompts/*.prompt.md` |
   | instruction | `rules/*.mdc`, `*.instructions.md` or `instructions/*.md` |
   | hook | `hooks/hooks.json` or `hooks/*/hooks.json` |
   | mcp | `.mcp.json` or `mcp.json` |

   palm skips `node_modules`, `docs`, `website`, `dist` and `build`.
   It skips `test`, `fixture`, `eval`, `example` and `template` folders too, singular or plural.
   It also skips installed copies such as `.claude/skills` and `.agents/skills`, and root `AGENTS.md`, `CLAUDE.md` and `GEMINI.md`.

2. Check every `SKILL.md`.

   - `name` is a slug of lowercase letters, digits and hyphens, and matches the folder name.
   - `description` says what the skill does and when to load it. `palm create` allows 1024 characters.
   - `metadata.version` or `version` sets the version; without one, palm shows the tag.
   - Scripts and references sit inside the skill folder. palm follows no symlink that leaves the repository.

3. Keep names to one path segment.

   An entity name starts with a letter or digit and continues with letters, digits, `.`, `_` or `-`.
   palm refuses to install a name with `/` or `..` in it.
   An agent's name is its file name without `.md` or `.agent.md`.
   A `name` with spaces becomes the display name, which Copilot and Gemini CLI show.

4. Declare every member in a plugin manifest.

   palm reads one manifest per plugin and never merges two.
   It picks the first it finds: `.claude-plugin/plugin.json`, `.cursor-plugin/plugin.json`, a root `plugin.json` with the agent-plugins `$schema`, `.codex-plugin/plugin.json`, then `gemini-extension.json`.

   | Manifest field | Effect |
   | --- | --- |
   | `skills` | adds folders to the default `skills/` scan |
   | `agents`, `commands` | replace the default folders |
   | `hooks`, `mcpServers` | merge with `hooks/hooks.json` and `.mcp.json` |
   | `name` | the plugin's name, before the marketplace entry name and the folder name |

   A skill the manifest does not reach is still installable, but palm warns about it.

5. List local plugins in `marketplace.json`.

   palm reads `.claude-plugin/marketplace.json` first, then the `.cursor-plugin`, `.github/plugin` and `.agents/plugins` versions.
   Each entry with a relative `source` becomes a plugin.
   A single entry with source `./` makes the whole repository one plugin.
   Entries in other repositories are listed for the user with the command to add them.

6. Test the repository with palm.

   ```sh
   palm install origin ./my-repo
   palm get --available -o my-repo
   ```

   The `detected:` rule in the first line says which layout palm used.
   Each warning names the file or plugin, and what palm did instead:

   <Capture name="b-author" title="~/project" />

   After each fix, run both commands again. `palm update origin my-repo` forces a fresh scan.

</Steps>

palm checks the files of every entity for hidden Unicode when it scans.
A bidi override or a tag character is critical: palm refuses to install that entity without `--force`.
A zero-width character is a warning.
Search your files for both before you tag a release.

## Check the result

Install one entity into a scratch project for all six harnesses:

```sh
palm install skill <name>@my-repo --target claude,codex,copilot,cursor,gemini,opencode
```

Each `i` line in the summary names a field one harness drops.
Keep what matters to the entity in the body, which every harness receives.
